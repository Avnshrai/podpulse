What it actually catches

Most K8s incidents are not log problems — they're misconfigured ConfigMaps, OOM kills, failed scheduling, image-pull errors, and bad rollouts. PodPulse watches all of them.

ConfigMap & Secret diff

Detects empty values, malformed JSON, removed keys, value changes — and tells you which pods mount them. The differentiator. No other tool does this proactively.

New error after deploy

Drain3 template clustering keyed by image-digest. Fires the moment a brand-new error template appears on a freshly rolled-out version.

K8s event fusion

OOMKilled, FailedScheduling, BackOff, FailedMount, ImagePullBackOff — categorized and surfaced as actionable issues, not raw rows.

Severity-aware filtering

Classifies every line by severity (JSON / logfmt / bracketed / keyword). Only WARN+ feeds the templater. Cuts ~70% of noise vs. naive log anomaly tools.

"What changed" timeline

Per-namespace timeline of every deploy + configmap edit + observed issue. The single most useful debugging view.

Audit + user onboarding

Tracks who-changed-what via managedFields (no audit-webhook). Onboard teammates as scoped ServiceAccounts with a one-click kubeconfig.

How it works

Two binaries, one Helm command. No agents on your apps, no OpenTelemetry, no SDK. Reads container stdout/stderr directly + watches the K8s API.

Install

One command. Templates-only storage by default — your raw logs never leave the cluster.

# Add the chart and install
helm repo add podpulse https://podpulse.github.io/charts
helm install podpulse podpulse/podpulse \
  --namespace podpulse --create-namespace \
  --set alerts.slack.webhook=$SLACK_WEBHOOK

# Open the dashboard
kubectl -n podpulse port-forward svc/podpulse-detector 8080:8080
open https://localhost:8080
